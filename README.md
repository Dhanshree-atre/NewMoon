# PrivateAirdrop

**A privacy-preserving token eligibility & claim platform on the Midnight Network.**

PrivateAirdrop lets an admin publish a rewards campaign whose *whole* lifecycle
— eligibility registration and claiming — runs inside zero-knowledge proofs. A
participant can prove "I hold a valid one-time code" and "I am entitled to the
reward" **without revealing their identity, their code, or any link between
their wallet and the claim**.

Built with **Compact** (Midnight's ZK smart-contract language), **Midnight.js**,
**React 18 + Vite + TypeScript**, and the **Midnight Lace / DApp Connector**
wallet.

## How it works

One deployed contract instance is **one airdrop campaign**. The admin:

1. Deploys the campaign with a name, a 32-byte campaign id, a reward per claim
   and a maximum number of claims.
2. Publishes one-time registration codes. Only `H(code)` is written on-chain —
   the raw codes are shared with eligible participants out-of-band.

A participant:

1. **Registers eligibility** — the circuit proves possession of a valid code in
   zero knowledge and records the commitment `C = H(secret, salt)` on-chain.
2. **Claims the reward** — the circuit proves ownership of an eligible
   commitment and appends a fresh nullifier `N = H(secret, campaignId)`.
3. **Verifies their claim** — anyone can check "is this nullifier a successful
   claim?" via the public `verifyClaim` circuit.

### Circuits

| Circuit | Purpose |
| --- | --- |
| `createCampaign` (constructor) | Admin deploys the campaign |
| `adminAddCode(_code)` | Admin publishes a hashed one-time registration code |
| `registerEligibility()` | Participant proves code possession, records `H(secret, salt)` |
| `claim()` | Participant proves eligibility and claims the reward |
| `verifyClaim(_nullifier)` | Public check that a nullifier was a successful claim |
| `closeCampaign()` | Admin closes the campaign (blocks new claims) |
| `computeCommitment` / `computeNullifier` / `computeCodeCommit` / `getDappPubKey` | Pure helpers used by off-chain code to compute the exact same hashes |

## Privacy model

**Public on-chain state** (any observer can read):

- `campaignName`, `campaignId`, `rewardPerClaim`, `maxClaims`, `status`
- `adminPubKey` — a dapp-scoped hash, reveals nothing about the admin's key
- `eligibilityList` — opaque commitment hashes `H(secret, salt)`
- `authorizedCodes` — hashes `H(code)`, never the codes themselves
- `claimedList` + `nullifierLog` — anti-double-claim bookkeeping and the
  anonymous "receipt" channel
- `lastVerificationResult` — the public answer to `verifyClaim`

**Private witnesses** (proved inside the ZK circuits, never written, logged or
rendered):

- `localAdminSk()` — the admin's secret key
- `localSecret()` / `localSalt()` — a participant's eligibility secret + salt
- `localCode()` — a participant's one-time registration code

A chain observer sees *that* valid proofs were produced and opaque hashes
changed — never *who* is eligible, *which* wallet claimed, or any secret/code.

In the frontend, the secret, salt and code are derived deterministically from
the wallet's shielded-coin public key, so the same wallet always produces the
same commitment/nullifier without persisting any secret on disk.

## Requirements

- **Node.js ≥ 22**
- **Docker** + Docker Compose (proof server / local devnet)
- The **Compact** compiler CLI (`compact`) on your `PATH` (used by `npm run compile`)
- For the frontend: **Midnight Lace** wallet extension, and a funded Preview

> installed, compile the contract in the browser/CLI flow only after the
> compiler is available, or use the pre-built artifacts from a previous
> `npm run compile`.

## Getting started

```bash
npm install

# 1. Local devnet (undeployed): starts node + indexer + proof server
npm run proof-server:start

# 2. Compile the Compact contract (5 minutes)
npm run compile

# 3. Tests (no network needed)
npm test

# 4. Deploy to the local devnet + try the CLI
npm run deploy                # devnet (undeployed)
npm run cli
```

The CLI offers:

1. Admin: add one-time eligibility code
2. Admin: close campaign
3. Participant: register eligibility (code)
4. Participant: claim reward
5. Participant: verify my claim
6. Show campaign state
7. Exit

> Switch networks any time with `npm run network preview`, or pass
> `--network preview` to individual commands.

## Testing

```bash
npm test
```

13 tests, ~2s, no network required. The suite drives the contract headlessly
(`tests/private-airdrop-simulator.ts`) and covers:

- **Admin**: campaign creation, code hashing (raw code never stored), access
  control (non-admins cannot add codes / close)
- **Registration**: only valid one-time codes register; codes are single-use;
  duplicate registration rejected; replay of a used code rejected
- **Claiming**: successful claim increments counters and adds commitment +
  nullifier; double claims rejected (commitment AND nullifier checks); claims
  rejected after close
- **Privacy (the important one)**: after registration and claiming, the
  **public ledger contains only hashes** — the tests byte-scan every public
  byte stream and assert that no raw secret, salt, code or private key appears
  anywhere on-chain
- **Pure circuit parity**: off-chain `computeCommitment` / `computeNullifier`
  outputs match the on-chain ledger values

## Deploying to a Midnight network

```bash
# 1. Proof server (needed for proving)
npm run proof-server:start

# 2. Deploy to a public network (preview | preprod)
npm run deploy -- --network preprod
```

The script generates a fresh 24-word wallet (saved to the gitignored
`.midnight-state.json`, printed for you to back up), syncs with the network,
waits for tNIGHT from the faucet
(preview: https://midnight-tmnight-preview.nethermind.dev,
preprod: https://midnight-tmnight-preprod.nethermind.dev),
registers DUST, deploys the contract, and prints the contract address.

Set the address in the frontend (see below) so the browser app connects to your
campaign.

> **Reference preprod deployment** (deployed from the browser app):
> `806413b7436003e625699f9166c49ec7eb783ea671a899542edc20530d2f3e1e`
> (set as `VITE_CONTRACT_ADDRESS` in `frontend/.env.local` to auto-join it).

> Prefer your own funded Lace wallet? Set `MIDNIGHT_WALLET_MNEMONIC` to your
> 24-word phrase — the seed derivation is Lace-compatible.

## Frontend

```bash
npm run frontend:install
npm run frontend:build        # syncs ZK artifacts + typechecks + builds (zero-error gate)
npm run frontend:dev          # Vite dev server
```

- Wallet discovery + connection through **Midnight Lace** (DApp Connector
  `4.x`), polling for the compatible wallet and connecting to `VITE_NETWORK_ID`
- ZK artifacts are served as static assets from `public/zk` via
  `FetchZkConfigProvider`; proofs are built against the configured proof server
- Public ledger state streams from the Preview indexer and updates live
- Admin panel: deploy a campaign, add codes, close
- Participant panel: register, claim, verify — each action labeled
  *"Proved without revealing your input"*

Deploys to Vercel or Netlify out of the box (`vercel.json`, `netlify.toml`,
`public/_redirects`).

## Architecture

```
┌────────────────────  Browser (React 18 + Vite)  ────────────────────┐
│  WalletConnect ── Lace DApp Connector (4.x) ── providers           │
│     AirdropAPI (deploy / join / admin / participant actions)       │
│     in-memory private state ── FetchZkConfigProvider(/zk)          │
└──────────────┬─────────────────────────────────────┬───────────────┘
               │ balanceTx + submitTx                │ public state$
               ▼                                     ▼
      Lace wallet / proof server            Preview indexer (GraphQL + WS)
               │                                     │
               └──────────────┬──────────────────────┘
                              ▼
               Midnight network (ledger + ZK verification)
```

The **CLI** (`src/`) reuses the same contract and witness derivation for the
no-browser flow, backed by the wallet SDK and a LevelDB private-state provider.
